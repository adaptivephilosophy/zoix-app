# Zoix (app iOS) / Zoix iOS App

**Français :** Application iOS gratuite de l'Adaptive Philosophy Foundation (Olympia, WA). L'accueil affiche [zoix.ai](https://zoix.ai). L'onglet Nouvelles est une liste native des articles du fil public utilisé par le site. Un mot français du jour est affiché dans l'application. Le bouton Faire un don ouvre la page de don dans Safari, en dehors de l'application.

**English:** A free iOS app from the Adaptive Philosophy Foundation (Olympia, WA). Home shows [zoix.ai](https://zoix.ai). Updates is a native list of articles from the public feed the site uses. A French word of the day is shown in the app. Donate opens the giving page in Safari, outside the app.

## Ce que fait l'application / What the app does

**Français :**

- **Accueil.** [zoix.ai](https://zoix.ai) dans une vue web. Retour, avance, et un bouton Accueil ramènent à zoix.ai. Un balayage depuis le bord gauche revient aussi en arrière. Retoucher l'onglet Accueil déjà choisi rouvre zoix.ai. Une ligne « Mot du jour » est sous la page. Les liens de don, de paiement, PayPal, Stripe et Cash App s'ouvrent dans Safari, pas dans la vue web.
- **Nouvelles.** Liste native du fil `https://ap-notion-articles.vercel.app/api/articles` (le même fil que la page d'accueil, environ 532 pages : titre, étiquettes, dates, lien). Recherche par titre ou étiquette, filtre par étiquette, tri par dernière mise à jour. Une page s'ouvre dans un navigateur intégré. La dernière liste réussie reste sur l'appareil si le réseau manque.
- **Mot du jour.** Mot français et sens anglais. Le fil public de Transparent Language est essayé en premier. Sinon, une liste enregistrée dans l'application est utilisée. Le mot de cette liste change à minuit, heure du Pacifique.
- **Faire un don.** Ouvre `https://www.paypal.com/ncp/payment/7LP669JW6TBYW` dans Safari. L'application ne touche pas aux cartes ni aux paiements.

**English:**

- **Home.** [zoix.ai](https://zoix.ai) in a web view. Back, forward, and a Home button return to zoix.ai. A swipe from the left edge also goes back. Tapping the Home tab when it is already selected opens zoix.ai again. A one-line word of the day sits under the page. Donate, payment, PayPal, Stripe, and Cash App links open in Safari, not in the web view.
- **Updates.** Native list from `https://ap-notion-articles.vercel.app/api/articles` (the same feed as the homepage, about 532 pages: title, tags, dates, link). Search by title or tag, filter by tag, sort by last updated. A page opens in an in-app browser. The last successful list stays on the device when the network fails.
- **Word of the day.** A French word and an English meaning. The public Transparent Language feed is tried first. Otherwise a list saved in the app is used. That saved word changes at midnight Pacific Time.
- **Donate.** Opens `https://www.paypal.com/ncp/payment/7LP669JW6TBYW` in Safari. The app does not handle cards or payments.

## Construction / Build

**Français :** Pas besoin d'un Mac. Le dépôt est public : les runners macOS de GitHub Actions sont gratuits.

Chaque pull request et chaque envoi sur `main` lancent [`.github/workflows/ci.yml`](.github/workflows/ci.yml). Ce workflow compile l'application et lance les tests sur un simulateur iPhone 17, sans signature.

La configuration Debug ne signe pas. La configuration Release utilise la signature automatique. C'est celle que le workflow TestFlight archive.

**English:** A Mac is not required. The repository is public, so GitHub Actions macOS runners are free.

Every pull request and every push to `main` runs [`.github/workflows/ci.yml`](.github/workflows/ci.yml). That workflow builds the app and runs the tests on an iPhone 17 simulator, with no signing.

The Debug configuration does not sign. The Release configuration uses automatic signing. The TestFlight workflow archives that configuration.

## TestFlight

**Français :** Le workflow [`.github/workflows/testflight.yml`](.github/workflows/testflight.yml) ne part pas tout seul sur une pull request. Il se lance à la main (Actions → TestFlight → Run workflow), ou quand une étiquette `v*` est poussée (par exemple `v1.0.0`).

Il archive avec `xcodebuild -allowProvisioningUpdates` et la clé d'API App Store Connect. Aucun certificat n'est stocké dans le dépôt. La clé est écrite dans le dossier temporaire du runner, puis effacée. Le journal ne doit pas afficher le contenu de la clé.

Secrets déjà prévus : `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (le texte complet du fichier `.p8`, avec les lignes BEGIN et END).

`APPLE_TEAM_ID` : les 10 caractères de l'équipe Apple, en variable ou en secret du dépôt. Les deux conviennent. Le workflow ne devine pas cette valeur et ne l'écrit pas dans le journal.

Le numéro de build est `numéro d'exécution × 100 + tentative`. Une nouvelle exécution obtient un numéro plus grand. Relancer la même exécution ne réutilise pas un numéro déjà accepté par Apple.

Pour vérifier la signature sans envoyer le fichier, lancer le workflow à la main et décocher **upload**.

**English:** [`.github/workflows/testflight.yml`](.github/workflows/testflight.yml) does not run on a pull request. Run it by hand (Actions → TestFlight → Run workflow), or push a `v*` tag (for example `v1.0.0`).

It archives with `xcodebuild -allowProvisioningUpdates` and the App Store Connect API key. No certificate is stored in the repository. The key is written into the runner's temp directory and then deleted. The log must not show the key text.

Secrets that are already expected: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (the full `.p8` text, including the BEGIN and END lines).

`APPLE_TEAM_ID`: the 10-character Apple Team ID, as a repository variable or a repository secret. Either one works. The workflow does not guess it and does not print it in the log.

The build number is `run number × 100 + attempt`. A new run gets a higher number. Re-running the same run does not reuse a number Apple already accepted.

To check signing without uploading, run the workflow by hand and turn **upload** off.

## Étapes qui restent au propriétaire / Steps only the owner can do

**Français :** Le premier envoi TestFlight échoue tant que ces étapes ne sont pas faites. Le workflow ne les invente pas.

1. Le compte Apple Developer de l'équipe qui publie Zoix est actif. Le Account Holder a accepté le contrat Apple Developer en cours.
2. Dans le dépôt GitHub : Settings → Secrets and variables → Actions. Créer `APPLE_TEAM_ID` avec les 10 caractères indiqués sur [developer.apple.com/account](https://developer.apple.com/account) (Membership details). Une variable ou un secret convient. Le secret déjà ajouté suffit.
3. Vérifier que `ASC_KEY_ID`, `ASC_ISSUER_ID` et `ASC_KEY_P8` sont présents et non expirés. La clé a le rôle **Admin** (accès aux certificats et aux profils). Un rôle App Manager peut envoyer un build, mais ne peut en général pas créer le certificat de distribution. La signature dans le nuage a besoin de ce droit. `ASC_KEY_P8` est le texte PEM du fichier `.p8`, pas une version encodée sans les lignes BEGIN / END.
4. Enregistrer l'App ID explicite `ai.zoix.app`, sans capacité supplémentaire (pas de notifications, pas d'achats intégrés, pas de domaines associés). La première archive peut le créer si la clé y est autorisée. Sinon, le créer dans Certificates, Identifiers & Profiles.
5. Dans App Store Connect, créer la fiche de l'app : nom **Zoix**, bundle ID **ai.zoix.app**, SKU **zoix-ios**, langue principale anglais. L'envoi est refusé si cette fiche n'existe pas. Cette création reste manuelle.
6. Accepter le contrat Free Apps (Agreements, Tax, and Banking). Le contrat Paid Apps n'est pas nécessaire : l'app est gratuite et n'a pas d'achat intégré. Ne pas décrire la fondation comme une organisation 501(c)(3) ni comme exonérée d'impôt dans la fiche, les captures ou les notes de revue. La reconnaissance IRS est en attente.
7. Confidentialité de l'app : répondre **Data Not Collected**. URL de politique : la page publique de [`docs/privacy.md`](docs/privacy.md) une fois ce fichier sur `main`, par exemple `https://github.com/adaptivephilosophy/zoix-app/blob/main/docs/privacy.md`. Chiffrement : l'app n'utilise que HTTPS standard et déclare `ITSAppUsesNonExemptEncryption` à faux. Si App Store Connect pose encore la question, répondre que l'app n'utilise pas de chiffrement non exempté.
8. L'essayeur interne doit être un utilisateur App Store Connect. Installer TestFlight sur l'appareil et accepter l'invitation après le traitement du build. Les essayeurs internes n'ont pas besoin de la revue Beta. Les essayeurs externes, si.
9. Quand les points 1 à 7 sont faits, lancer Actions → TestFlight sur la branche `main`. On peut d'abord décocher upload pour vérifier la signature, puis relancer avec l'envoi. Ne pas relancer la même exécution en espérant un nouveau numéro : lancer une nouvelle exécution.
10. L'icône d'accueil est l'arbre central du logo, sans texte, dans `Zoix/Assets.xcassets/AppIcon.appiconset/AppIcon.png` (1024×1024, sans transparence). `scripts/generate-app-icon.py` la reconstruit à partir de `scripts/brand/adaptive-philosophy-logo.png`.

Contact public, si la fiche en a besoin : DanBoice@adaptivephilosophy.foundation. Ne pas y mettre d'adresse personnelle ni d'information de santé.

**English:** The first TestFlight upload fails until these steps are done. The workflow does not invent them.

1. The Apple Developer account for the team that will ship Zoix is active. The Account Holder has accepted the current Apple Developer Program License Agreement.
2. In the GitHub repository: Settings → Secrets and variables → Actions. Create `APPLE_TEAM_ID` with the 10 characters shown at [developer.apple.com/account](https://developer.apple.com/account) (Membership details). A variable or a secret works. The secret that is already there is enough.
3. Confirm `ASC_KEY_ID`, `ASC_ISSUER_ID`, and `ASC_KEY_P8` are present and not expired. The key needs the **Admin** role (access to certificates and profiles). An App Manager key can upload a build, but usually cannot create the distribution certificate. 4. Register the explicit App ID `ai.zoix.app`, with no extra capabilities (no push, no in-app purchase, no associated domains). The first archive may create it if the key is allowed to. Otherwise create it in Certificates, Identifiers & Profiles.
5. In App Store Connect, create the app record: name **Zoix**, bundle ID **ai.zoix.app**, SKU **zoix-ios**, primary language English. The upload is rejected if this record does not exist. Creating it stays a manual step.
6. Accept the Free Apps agreement (Agreements, Tax, and Banking). The Paid Apps agreement is not required: the app is free and has no in-app purchase. Do not describe the foundation as a 501(c)(3) or as tax-exempt in the listing, screenshots, or review notes. IRS recognition is pending.
